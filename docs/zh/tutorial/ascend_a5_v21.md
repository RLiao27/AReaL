# AReaL v2.1.0 Ascend A5 适配记录

本文整理此前在 Ascend A5 上进行的适配与实验。基线为 AReaL `v2.1.0`（提交
`ecc8b0e4dfb4e3965f67121a5c87866a07c390ae`），开发分支为 `feature/ascend-a5-bf16`；部分实现参考了
`ascend-950-dev` 分支。过程记录见 [A5 开发日志](../../../ASCEND_A5_DEVLOG.md)。

## 已验证范围

- 单机 Ascend A5，Qwen3-8B，BF16，FSDP 训练和 vLLM Ascend 推理。
- AReaL v2 训练服务通过磁盘快照向推理服务更新全量权重；两步冒烟中观察到非零梯度和两次成功同步。
- GSM8K 训练及训练前后评估已完成。结果只覆盖该模型、配置和评分方式，不能推断所有模型或配置均已完成适配。

## 代码改动

| 部分           | 改动                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| FSDP           | Qwen3 使用 SDPA 和打包序列时，将 attention mask 交由模型根据 position IDs 构造，避免跨样本注意力。          |
| v2 权重同步    | 全参数训练可显式选择 `actor.weight_update_mode: disk`；未选择 disk 的原有 AWEX 路径保留。LoRA 仍使用 disk。 |
| vLLM 服务      | 兼容 vLLM 0.23 的 API 导入，并提供 disk 权重加载接口。                                                      |
| 权重更新安全性 | 所有推理 worker 加载成功后，按配置清理临时快照；加载失败保留快照，训练控制器报告同步失败。                  |
| 推理数据代理   | 转发 `chat_template_kwargs`，使 Qwen3 的思考模式配置生效。                                                  |
| 配置与测试     | NPU GSM8K 示例使用 disk；补充打包注意力、代理参数和权重同步相关回归测试。                                   |

NPU 示例位于
[`examples/math/gsm8k_grpo_npu.yaml`](../../../examples/math/gsm8k_grpo_npu.yaml)。它展示相关配置，并不包含下述严格评估实验的全部启动脚本和环境。

## GSM8K 实验

历史实验使用训练集 7,217 条、从训练集留出的验证集 256 条，以及官方测试集 1,319 条。训练使用 4 卡 FSDP 和 1 卡推理，batch size
64，每题采样 4 次，学习率 `1e-6`，最多生成 512 token，训练 112 步。评估使用贪心解码，并按最后一个完整的 boxed 答案进行严格评分。

| 权重          |  官方测试集 | 准确率 |
| ------------- | ----------: | -----: |
| 原始 Qwen3-8B | 1208 / 1319 | 91.58% |
| 第 112 步权重 | 1223 / 1319 | 92.72% |

两者相差 1.14 个百分点；逐题比较，47 题由错变对，32 题由对变错。验证集中第 25、50、75、100、112 步依次为 244、246、247、248、248 /
256，因此最终权重与第 100 步在该验证集上并列，不能据此断言最终权重是最佳权重。较早一次宽松评分产生的结果不可靠，不应与上述严格评分结果比较。

上述数据来自历史实验记录，本次整理未重新运行。严格评估和训练专用脚本此前已从仓库移至实验归档，因此仅凭当前仓库不能完整复现实验；复现还需对应模型、数据、脚本和运行环境。

## 实验环境与限制

历史环境为 Python 3.12.13、PyTorch 2.10.0+cpu、torch-npu 2.10.0.post2、CANN 9.0.1、Transformers
5.5.4、vLLM 0.23.0+empty、vLLM Ascend 0.23.0rc2.dev107+geaefc536d 和 MindSpeed
0.16.0。实验通过额外 Python 路径覆盖 NumPy 1.26.4、SciPy 1.13.1 和 torchvision 0.25.0+cpu；其中 NumPy
版本与 MindSpeed 声明的约束冲突，尚需建立一致、可复现的环境。

Qwen3.5 的 GDN 变长打包反向曾出现非有限梯度，相关实验补丁已移出仓库，其根因和完整训练尚未验证。MXFP8、AWEX/XCCL 在 A5 上的 v2
权重同步、多机及其他模型也不属于本次已验证范围。后续应先解决环境依赖和 Qwen3.5 GDN 数值问题，再分别验证对应模型、并行策略及 MXFP8。
